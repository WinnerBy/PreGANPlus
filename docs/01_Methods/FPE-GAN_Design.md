## 📋 概述

### 方法定位

FPE-GAN (Fault Prediction Encoder GAN) 是基础的GAN方法，使用FPE（Fault Prediction Encoder）编码器进行故障预测和调度优化。它是在传统方法基础上引入GAN框架的首次尝试。

### 核心设计理念

1. **FPE编码器**: 结合GRU和GAT（Graph Attention Network）进行故障预测
2. **标准GAN**: 使用标准Generator和Discriminator进行调度优化
3. **故障预测驱动**: 只有在检测到故障时才进行迁移决策

### 方法特点

- **基础性**: 作为后续方法的基础，提供了GAN框架的核心实现
- **故障预测**: 通过FPE编码器进行故障预测，避免不必要的迁移
- **简单有效**: 相对简单的架构，易于理解和实现

## 🏗️ 架构设计

### FPE编码器架构

#### 网络结构

```python
FPE_16(
    gru: GRU(48 -> 3)                    # 时间序列编码
    gat: GAT(16 nodes, 3 -> 16)          # 图注意力网络
    mha: MultiheadAttention(19, 1)       # 多头注意力
    encoder: Linear(57 -> 160)           # 潜在空间编码
    anomaly_decoder: Linear(10 -> 2)     # 异常检测解码器
    prototype_decoder: Linear(10 -> 2)   # 原型向量解码器
)
```

#### 输入输出

- **输入**:
  - `t`: [3, 48] - 时间序列数据（3个时间步，16主机×3指标）
  - `s`: [16, 16] - 当前调度矩阵
- **输出**:
  - `anomaly_scores`: [16, 2] - 每个主机的异常检测概率
  - `prototypes`: [16, 2] - 每个主机的原型向量

#### 关键组件详解

##### 1. GRU时间序列编码

- **输入**: [3, 48] - 3个时间步，每个时间步48维特征（16主机×3指标）
- **输出**: [3, 3] - 3个时间步，每个时间步3维隐藏状态
- **作用**: 捕获时间序列的短期依赖关系

##### 2. GAT图注意力网络

- **输入**: [3, 16, 3] - 3个时间步，16个节点（主机），每个节点3维特征
- **输出**: [3, 16, 16] - 3个时间步，16个节点，每个节点16维特征
- **作用**: 建模主机之间的空间依赖关系（通过图注意力机制）
- **图结构**: 16节点全连接图

##### 3. 多头注意力融合

- **输入**: 
  - GRU输出: [3, 1, 3]
  - GAT输出: [3, 1, 16]
  - 拼接后: [3, 1, 19]
- **输出**: [3, 1, 19] - 经过注意力机制融合的特征
- **作用**: 融合时间序列特征和图结构特征

##### 4. 潜在空间编码

- **输入**: [57] - 展平后的融合特征（3×19=57）
- **输出**: [16, 10] - 16个主机的潜在表示
- **作用**: 将融合特征编码到潜在空间

##### 5. 异常检测解码器

- **输入**: [10] - 每个主机的潜在表示
- **输出**: [2] - 异常检测概率（正常/异常）
- **作用**: 判断每个主机是否发生故障

##### 6. 原型向量解码器

- **输入**: [10] - 每个主机的潜在表示
- **输出**: [2] - 原型向量（用于Generator）
- **作用**: 为每个主机生成特征表示，用于调度优化

---

### Generator架构

#### 网络结构

```python
Gen_16(
    delta: Sequential(
        Linear(288 -> 64),               # 288 = 16*2 (prototypes) + 16*16 (schedule)
        LeakyReLU(True),
        Linear(64 -> 256),               # 256 = 16*16 (schedule delta)
        Tanh()
    )
)
```

#### 输入输出

- **输入**:
  - `e`: [16, 2] - FPE编码器输出的原型向量
  - `s`: [16, 16] - 当前调度矩阵
- **输出**: `new_schedule`: [16, 16] - 新的调度矩阵

#### 工作原理

1. **特征拼接**: 将原型向量和调度矩阵展平并拼接 `[16*2 + 16*16 = 288]`
2. **增量生成**: 通过MLP生成调度增量 `[16*16 = 256]`
3. **调度更新**: `new_schedule = s + 4 * delta`

**注意**: 增量乘以4是为了增加更新幅度，使调度变化更明显。

---

### Discriminator架构

#### 网络结构

```python
Disc_16(
    probs: Sequential(
        Linear(512 -> 64),               # 512 = 16*16*2 (original + new schedule)
        LeakyReLU(True),
        Linear(64 -> 2),
        Softmax(dim=0)
    )
)
```

#### 输入输出

- **输入**:
  - `o`: [16, 16] - 原始调度矩阵
  - `n`: [16, 16] - 新调度矩阵
- **输出**: `probs`: [2] - 分类概率（原始更好 vs 新调度更好）

#### 工作原理

1. **特征拼接**: 将原始调度和新调度展平并拼接 `[512]`
2. **分类**: 通过MLP判断哪个调度更好
3. **输出**: 二元分类概率

## 🎓 训练流程

### 编码器训练

#### 训练数据

- **来源**: 阶段1收集的数据（当前推荐配置：400 步×8 容器，见 [Stage1_Data_And_Analysis](../02_Experiments/Stage1_Data_And_Analysis.md)）
- **格式**: 
  - `time_series.npy`: [timesteps, 48] - 时间序列数据（16 主机×3 指标）
  - `schedule_series.npy`: [timesteps, 16, 16] - 调度序列数据
  - `fault_history.pkl`: ADE 故障标签（与 Stage1 一致）

#### 训练参数

- **Epochs**: 300（`recovery/PreGANSrc/src/constants.py` 中 `num_epochs = 300`）
- **学习率**: 默认（constants 与优化器）
- **优化器**: Adam
- **损失函数**: 异常检测损失 + 原型向量（triplet）损失

#### 训练流程

**核心机制**: FPE编码器的训练是在运行 `main.py` 时自动进行的，不需要单独的训练脚本。

**自动训练触发机制**:
- 在 `recovery/PreGAN.py` 的 `load_models()` 方法中，如果 checkpoint 不存在或 `epoch == -1`，会自动调用 `train_model()` 进行训练
- 训练完成后，编码器会被冻结（`freeze(self.model)`），在后续使用中不再更新参数

**详细流程**:
1. **数据加载**: 加载阶段1收集的1000步数据（来自 `recovery/PreGANSrc/data/simulator/`）
2. **窗口化**: 将时间序列转换为窗口数据（窗口大小=3）
3. **前向传播**: 运行编码器，得到异常检测分数和原型向量
4. **损失计算**: 计算异常检测损失和原型向量损失
5. **反向传播**: 更新编码器参数
6. **保存checkpoint**: 每10个epoch保存一次到 `recovery/PreGANSrc/checkpoints/simulator_FPE_16.ckpt`

**训练参数**:
- Epochs: 300（在 `constants.py` 中 `num_epochs = 300`）
- 学习率: 默认
- 优化器: Adam
- 损失函数: 异常检测损失 + 原型向量损失

**重新训练方法**:
- 删除 checkpoint 文件，下次运行时会自动重新训练
- 或修改 checkpoint 中的 epoch 为 -1

### GAN训练

#### 训练参数

- **Generator学习率**: 0.00005
- **Discriminator学习率**: 0.00005
- **优化器**: AdamW
- **损失函数**: BCELoss（二元交叉熵）

#### 训练流程（每个间隔）

1. **异常检测**: 运行FPE编码器，检测故障
2. **如果检测到故障**:
   - **Discriminator训练**:
     - 生成新调度（Generator）
     - 运行模拟，评估新调度和原始调度
     - 计算损失，更新Discriminator
   - **Generator训练**:
     - 生成新调度（Generator）
     - Discriminator评估新调度
     - 计算损失，更新Generator
3. **保存checkpoint**: 每10个间隔保存一次

## 🔍 推理流程

### 异常检测

1. **获取时间序列数据**: 从环境统计数据获取最新的时间序列
2. **数据预处理**: 归一化和窗口化
3. **运行编码器**: 得到异常检测分数和原型向量
4. **判断**: 如果所有主机都未检测到异常，返回原始决策

### 调度决策生成

1. **生成原型向量**: 只保留检测到异常的主机的原型向量
2. **生成新调度**: 使用Generator生成新调度
3. **评估**: Discriminator评估新调度是否优于原始调度
4. **决策选择**: 
   - 如果原始调度更好，返回原始决策
   - 否则，应用新调度

## 🔑 关键技术点

### 1. FPE编码器的设计

**设计思想**: 结合时间序列编码（GRU）和图结构编码（GAT）进行故障预测。

**实现方式**:
- GRU捕获时间序列的短期依赖
- GAT建模主机之间的空间依赖（全连接图）
- 多头注意力融合时间序列特征和图结构特征

**效果**: 
- 能够同时捕获时间依赖和空间依赖
- 相比纯时间序列方法，具有更强的故障预测能力

### 2. 故障预测驱动的迁移

**设计思想**: 只有在检测到故障时才进行迁移，避免不必要的迁移。

**实现方式**:
- FPE编码器进行异常检测
- 只有检测到异常的主机才参与迁移决策
- 未检测到异常时，直接返回原始决策

**效果**: 
- 减少不必要的迁移
- 相比传统方法，迁移数显著减少（21%-84%）

### 3. GAN框架的调度优化

**设计思想**: 使用GAN学习更好的调度策略。

**实现方式**:
- Generator生成新调度
- Discriminator评估新调度的优劣
- 通过对抗训练，学习优化调度

**效果**: 
- 能够学习到更好的调度策略
- 相比传统方法，在多个指标上表现更好

## 📊 与 TF-GAN 的对比

| 方面 | FPE-GAN | TF-GAN | 差异 |
|------|---------|--------|------|
| 编码器 | FPE_16 | Transformer_16 | Transformer 更强的序列建模能力 |
| Generator | Gen_16 | Gen_16 | 相同 |
| Discriminator | Disc_16 | Disc_16 | 相同 |
| 训练机制 | 离线训练 | 离线+在线调优 | TF-GAN 有在线调优 |

**当前实验数值**（Stage3 挑选 5 次，600 步×10 容器）见 [Stage3_Results_Analysis](../03_Results/Stage3_Results_Analysis.md)；上表为历史单次运行参考，以 Stage3 文档为准。

## 💡 设计优势

1. **故障预测**: 通过FPE编码器进行故障预测，避免不必要的迁移
2. **简单有效**: 相对简单的架构，易于理解和实现
3. **迁移控制**: 相比传统方法，迁移数显著减少（21%-84%）
4. **响应时间**: 在响应时间上表现优秀
