```python
def gethostStat(self):
    """获取主机统计信息"""
    cpu = psutil.cpu_percent()  # CPU使用率（0-100%）
    memory = psutil.virtual_memory()[2]  # 内存使用率（0-100%）
    disk = psutil.disk_usage('/')
    disk_total = disk.used / (1024 * 1024)  # 磁盘使用量（MB）
    payload = {"ip": self.hostIP, "cpu": cpu, "memory": memory, "disk": disk_total}
    return rc, json.dumps(payload)
```

**关键点**：
- 使用`psutil`库获取真实的系统资源使用情况
- CPU、内存以百分比形式返回（0-100%）
- 数据是实时的，充满噪声

### 3. 时间序列数据存储

**位置**: `stats/Stats.py`

```python
def saveHostInfo(self):
    """保存主机信息到时间序列"""
    # 获取所有主机的CPU、RAM、Disk使用情况
    cpulist = [host.getCPU() for host in self.env.hostlist]  # CPU使用率（0-100）
    ramlist = [host.getCurrentRAM()[0] for host in self.env.hostlist]  # RAM使用量（MB）
    disklist = [host.getCurrentDisk()[0] for host in self.env.hostlist]  # Disk使用量（MB）
    
    # 组合成时间序列数据点：[cpu_0, ram_0, disk_0, cpu_1, ram_1, disk_1, ...]
    datapoint = np.concatenate([[cpulist[i], ramlist[i], disklist[i]] 
                                for i in range(len(cpulist))]).reshape(1, -1)
    self.time_series = np.append(self.time_series, datapoint, axis=0)
```

**数据格式**：
- `time_series`: `[n_timesteps, n_hosts * 3]`
- 每个主机3个维度：`[CPU%, RAM_MB, Disk_MB]`
- 例如16个主机：`[n_timesteps, 48]`

    """运行故障预测和恢复模型"""
    # 1. 运行encoder检测异常
    schedule_data = torch.tensor(self.env.scheduler.result_cache).double()
    anomaly, prototype = self.run_encoder(schedule_data)

## 🔍 关键发现

### 1. 代码中没有实现ADE

**证据**：
- 搜索代码，没有找到基于90%阈值的故障检测逻辑
- 没有找到持续60秒的故障持续时间检查
- 没有找到故障类型分类（CPU、Network、RAM）

**实际实现**：
- 使用统计方法（percentile、z-score等）标记异常
- 在训练阶段，从历史数据中生成异常标签
- 在推理阶段，使用训练好的encoder模型检测异常

### 2. 数据收集流程是正确的

**证据**：
- ✅ 通过Docker API获取实时资源使用情况
- ✅ 使用`psutil`获取主机资源使用情况
- ✅ 数据存储在时间序列中（`stats.time_series`）
- ✅ 数据格式包含CPU、RAM、Disk等信息

### 3. 故障处理流程

**流程**：
1. **数据收集**：每个interval收集资源使用情况
2. **数据存储**：存储在`stats.time_series`中
3. **异常检测**：使用训练好的encoder模型检测异常
4. **故障恢复**：如果检测到异常，通过GAN生成新的调度决策

## 💡 结论

### 代码现状

1. **数据收集**：✅ 正确实现
   - 通过Docker API和psutil获取实时资源数据
   - 数据存储在时间序列中

2. **故障检测**：❌ 与论文描述不同
   - 论文：基于ADE的阈值+持续时间检测
   - 代码：使用统计方法（percentile等）标记异常

3. **故障处理**：✅ 基本正确
   - 检测到异常后，通过GAN生成新的调度决策

### 改进方向

如果要实现论文中描述的ADE逻辑，需要：

1. **实现ADE模块**：
   - 基于90%阈值检测CPU、RAM、Network过载
   - 检查持续60秒的故障持续时间
   - 分类故障类型（CPU、Network、RAM）

2. **修改标签生成逻辑**：
   - 在训练阶段，使用ADE逻辑生成故障标签
   - 替代当前的统计方法

3. **在推理阶段使用ADE**：
   - 可以同时使用ADE和encoder模型
   - ADE作为ground truth，encoder作为预测模型
