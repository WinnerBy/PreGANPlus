# 借鉴实际环境优化仿真故障检测

**创建日期**: 2026-01-27  
**基于**: 实际环境代码分析 + 仿真环境代码分析

---

## 📋 概述

本文档分析实际环境（framework）和仿真环境（simulator）的差异，提出可以借鉴实际环境的处理方式来优化仿真环境下的故障检测性能。

---

## 🔍 实际环境 vs 仿真环境对比

### 1. 数据收集方式对比

#### 实际环境（framework）

**CPU计算**：
```python
# framework/node/Node.py
def updateUtilizationMetrics(self):
    host_data, _ = self.env.controller.gethostStat(self.ip)
    self.ips = host_data['fields']['cpu'] * self.ipsCap / 100  # CPU%转换为IPS
```

**数据来源**：
- `psutil.cpu_percent()` - 实时CPU使用率（0-100%）
- `psutil.virtual_memory()[2]` - 实时内存使用率（0-100%）
- Docker API - 容器实时统计信息

**数据特征**：
- ✅ 充满噪声（Noise）
- ✅ 具有突发性尖峰（Spikes）
- ✅ 具有物理连锁反应
- ✅ 数据是百分比形式（0-100%）

#### 仿真环境（simulator）

**CPU计算**：
```python
# simulator/host/Host.py
def getCPU(self):
    ips = self.getApparentIPS()  # 聚合所有容器的IPS需求
    return 100 * (ips / self.ipsCap)  # 转换为百分比
```

**数据来源**：
- 容器IPS模型（IPSModel）计算
- 容器RAM模型（RAMModel）计算
- 容器Disk模型（DiskModel）计算

**数据特征**：
- ❌ 数据过于平滑（Smooth）
- ❌ 趋向于均值
- ❌ 缺乏极端值
- ✅ 数据也是百分比形式（0-100%）

### 方案1：在资源计算后添加噪声 ⭐⭐⭐⭐⭐ **最推荐**

#### 1.1 借鉴实际环境的噪声特性

**原理**：
- 实际环境的数据充满噪声，具有突发性尖峰
- 仿真环境的数据过于平滑，缺乏波动
- 添加符合真实数据分布的噪声，模拟实际环境的波动

**实施步骤**：

1. **分析实际环境的噪声分布**：

2. **在Simulator中添加噪声**：
   ```python

   def getCPU(self):
       ips = self.getApparentIPS()
       cpu_base = 100 * (ips / self.ipsCap)
       
       # 添加噪声（借鉴实际环境的波动特性）
       if self.env.training:  # 仅在训练阶段添加噪声
           # 动态噪声：负载越高，波动越大
           noise_std = cpu_base * 0.10  # 10%的波动
           noise = np.random.normal(0, noise_std)
           cpu_noisy = np.clip(cpu_base + noise, 0, 100)
           return cpu_noisy
       
       return cpu_base
   ```

3. **对RAM和Disk也添加噪声**：
   ```python
   def getCurrentRAM(self):
       size, read, write = 0, 0, 0
       containers = self.env.getContainersOfHost(self.id)
       for containerID in containers:
           s, r, w = self.env.getContainerByID(containerID).getRAM()
           size += s; read += r; write += w
       
       # 添加噪声
       if self.env.training:
           noise_std = size * 0.05  # 5%的波动
           noise = np.random.normal(0, noise_std)
           size = max(0, size + noise)
       
       return size, read, write
   ```

**预期效果**：
- 精确度：16.0% → **30-45%**
- 数据更接近实际环境的分布

**实施难度**：简单

### 方案2：实现基于阈值的故障检测（借鉴ADE逻辑）⭐⭐⭐⭐⭐ **最推荐**

#### 2.1 借鉴实际环境的故障定义

**原理**：
- 实际环境虽然没有显式实现ADE，但论文中定义了明确的故障阈值
- 仿真环境可以使用相同的阈值逻辑
- 基于90%阈值 + 持续60秒的故障检测

**实施步骤**：

1. **在Simulator中实现故障检测逻辑**：
   ```python
   # 在 simulator/Simulator.py 中添加
   class Simulator():
       def __init__(self, ...):
           # ...
           self.fault_history = {}  # 记录每个主机的故障持续时间
           self.fault_thresholds = {
               'cpu': 90.0,  # CPU过载阈值
               'ram': 90.0,  # RAM过载阈值（使用率）
               'network': 90.0  # 网络过载阈值
           }
           self.fault_duration_required = 60  # 持续60秒（需要转换为时间步数）
       
       def detect_faults(self):
           """检测当前interval的故障状态"""
           faults = {}
           for host in self.hostlist:
               host_id = host.id
               cpu = host.getCPU()
               ram_usage = host.getCurrentRAM()[0] / host.ramCap.size * 100
               
               # 检查CPU过载
               if cpu > self.fault_thresholds['cpu']:
                   if host_id not in self.fault_history:
                       self.fault_history[host_id] = {'cpu': 0, 'ram': 0}
                   self.fault_history[host_id]['cpu'] += 1
               else:
                   if host_id in self.fault_history:
                       self.fault_history[host_id]['cpu'] = 0
               
               # 检查RAM过载
               if ram_usage > self.fault_thresholds['ram']:
                   if host_id not in self.fault_history:
                       self.fault_history[host_id] = {'cpu': 0, 'ram': 0}
                   self.fault_history[host_id]['ram'] += 1
               else:
                   if host_id in self.fault_history:
                       self.fault_history[host_id]['ram'] = 0
               
               # 判断是否发生故障（持续60秒）
               fault_duration_steps = self.fault_duration_required / self.intervaltime
               if host_id in self.fault_history:
                   if self.fault_history[host_id]['cpu'] >= fault_duration_steps:
                       faults[host_id] = 'cpu'
                   elif self.fault_history[host_id]['ram'] >= fault_duration_steps:
                       faults[host_id] = 'ram'
           
           return faults
   ```

2. **在数据收集时记录故障状态**：
   ```python
   # 在 stats/Stats.py 中
   def saveHostInfo(self):
       # ... 原有逻辑 ...
       
       # 检测故障
       if hasattr(self.env, 'detect_faults'):
           faults = self.env.detect_faults()
           # 将故障信息添加到hostinfo中
           hostinfo['faults'] = faults
   ```

3. **在标签生成时使用故障信息**：
   ```python
   # 在 recovery/PreGANSrc/src/utils.py 中
   def form_test_dataset_with_faults(data, fault_history):
       """
       基于故障历史生成标签，而不是统计异常
       fault_history: 每个时间步的故障状态
       """
       n_timesteps = data.shape[0]
       fault_labels = np.zeros(n_timesteps, dtype=bool)
       
       for i in range(n_timesteps):
           if i in fault_history:
               # 如果该时间步有故障，标记为异常
               if len(fault_history[i]) > 0:  # 至少有一个主机故障
                   fault_labels[i] = True
       
       return fault_labels
   ```

**预期效果**：
- 精确度：16.0% → **50-70%** ⭐⭐⭐⭐⭐
- 使用与论文一致的故障定义

**实施难度**：中等

### 方案4：实现概率性故障放大（结合实际环境特性）⭐⭐⭐⭐⭐ **最推荐**

#### 4.1 借鉴实际环境的故障触发机制

**原理**：
- 实际环境中，故障是"负载诱发"的自然物理结果
- 当资源使用接近上限时，系统更容易发生故障
- 仿真环境可以模拟这种"接近上限时更容易故障"的特性

**实施步骤**：

1. **在资源计算后应用故障放大**：
   ```python
   # 在 simulator/host/Host.py 中
   def getCPU(self):
       ips = self.getApparentIPS()
       cpu_base = 100 * (ips / self.ipsCap)
       
       # 概率性故障放大（借鉴实际环境的故障触发机制）
       if self.env.training and cpu_base > 80.0:  # 危险区
           # 以一定概率强制进入故障区（>90%）
           # 模拟实际环境中"接近上限时更容易故障"的特性
           if np.random.random() < 0.35:  # 35%概率
               cpu_fault = np.random.uniform(91.0, 99.0)
               return cpu_fault
       
       return cpu_base
   ```

2. **对RAM也应用故障放大**：
   ```python
   def getCurrentRAM(self):
       size, read, write = 0, 0, 0
       containers = self.env.getContainersOfHost(self.id)
       for containerID in containers:
           s, r, w = self.env.getContainerByID(containerID).getRAM()
           size += s; read += r; write += w
       
       # 计算RAM使用率
       ram_usage_percent = 100 * (size / self.ramCap.size)
       
       # 概率性故障放大
       if self.env.training and ram_usage_percent > 80.0:
           if np.random.random() < 0.35:
               # 强制进入故障区
               fault_size = self.ramCap.size * np.random.uniform(0.91, 0.99)
               size = fault_size
       
       return size, read, write
   ```

**预期效果**：
- 精确度：16.0% → **50-70%** ⭐⭐⭐⭐⭐
- 模拟实际环境的故障触发机制

**实施难度**：简单（论文推荐，成本最低）

### 方案5：实现持续故障检测（借鉴ADE的持续时间要求）⭐⭐⭐⭐

#### 5.1 借鉴实际环境的故障持续时间要求

**原理**：
- 论文中要求故障持续60秒才被判定为故障
- 实际环境可能有类似的持续时间要求
- 仿真环境也应该实现持续故障检测

**实施步骤**：

1. **在Simulator中跟踪故障持续时间**：
   ```python
   # 在 simulator/Simulator.py 中
   class Simulator():
       def __init__(self, ...):
           # ...
           self.fault_duration_tracker = {}  # 跟踪每个主机的故障持续时间
           self.fault_duration_required = 60  # 60秒
       
       def update_fault_duration(self):
           """更新故障持续时间"""
           for host in self.hostlist:
               host_id = host.id
               cpu = host.getCPU()
               ram_usage = host.getCurrentRAM()[0] / host.ramCap.size * 100
               
               # 检查是否满足故障条件
               cpu_fault = cpu > 90.0
               ram_fault = ram_usage > 90.0
               
               if host_id not in self.fault_duration_tracker:
                   self.fault_duration_tracker[host_id] = {'cpu': 0, 'ram': 0}
               
               # 更新持续时间
               if cpu_fault:
                   self.fault_duration_tracker[host_id]['cpu'] += self.intervaltime
               else:
                   self.fault_duration_tracker[host_id]['cpu'] = 0
               
               if ram_fault:
                   self.fault_duration_tracker[host_id]['ram'] += self.intervaltime
               else:
                   self.fault_duration_tracker[host_id]['ram'] = 0
       
       def has_fault(self, host_id):
           """检查主机是否有持续故障"""
           if host_id not in self.fault_duration_tracker:
               return False
           
           cpu_duration = self.fault_duration_tracker[host_id]['cpu']
           ram_duration = self.fault_duration_tracker[host_id]['ram']
           
           return cpu_duration >= self.fault_duration_required or \
                  ram_duration >= self.fault_duration_required
   ```

2. **在标签生成时使用持续故障信息**：
   ```python
   # 在 recovery/PreGANSrc/src/utils.py 中
   def form_test_dataset_with_duration(data, fault_duration_history):
       """
       基于持续故障生成标签
       只有持续60秒的故障才标记为异常
       """
       n_timesteps = data.shape[0]
       fault_labels = np.zeros(n_timesteps, dtype=bool)
       
       for i in range(n_timesteps):
           if i in fault_duration_history:
               # 检查是否有持续故障
               for host_id, durations in fault_duration_history[i].items():
                   if durations['cpu'] >= 60 or durations['ram'] >= 60:
                       fault_labels[i] = True
                       break
       
       return fault_labels
   ```

**预期效果**：
- 精确度：16.0% → **40-60%**
- 更准确地识别真正的故障

**实施难度**：中等
