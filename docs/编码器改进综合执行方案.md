## 📊 问题根源分析

### 三层级问题

```
第1层：模型训练问题
├─ 当前精准率: 15.42%
├─ 改进了参数: ANOMALY_WEIGHT 100→10, Focal Loss, num_epochs 50→100
└─ 但仍难以达到70%

↓

第2层：数据标签问题  
├─ 故障样本: 291 (1.82%)
├─ 正常样本: 15,741 (98.18%)
└─ **极度类别不平衡导致模型学习困难**

↓

第3层：数据生成问题 (根本原因)
├─ 当前配置: NEW_CONTAINERS=5, NUM_SIM_STEPS=1000
├─ 容器负载过低→触发故障机制困难
└─ 需要增加故障样本来改善
```

### 为什么改进参数还不够？

| 解决方案 | 有效范围 | 当前情况 | 效果 |
|:---:|:---:|:---:|:---:|
| 参数调整 (权重) | 不平衡比例 90:10~95:5 | 98:2 | ❌ 超出范围 |
| Focal Loss | 不平衡比例 95:5~97:3 | 98:2 | ❌ 超出范围 |
| 数据增强 (过采样) | 不平衡比例 95:5 | 98:2 | ⚠️ 有限帮助 |
| **生成更多故障样本** | **任何比例** | **98:2** | **✅ 根本解决** |

**结论**: 必须先解决数据生成问题，才能让模型训练改进有效。

## 💡 技术原理

### 为什么增加NEW_CONTAINERS会增加故障？

```
当前机制: 工作负载 → 容器部署 → CPU/RAM使用率上升 → 触发ADE故障检测

故障判定条件:
  IF (CPU > 90% AND RAM > 90% for 5+ intervals) THEN 故障

改进效果:
  - NEW_CONTAINERS: 5 → 15 (3倍)
    → 系统负载增加
    → 更容易超过90%阈值
    → 更容易触发故障
  
  - NUM_SIM_STEPS: 1000 → 2000 (2倍)
    → 更长的运行时间
    → 更多机会形成5-interval连续超限
    → 故障样本数量增加
```

### 为什么这解决了模型问题？

```
根本问题: 极度类别不平衡 (98:2)
       ↓
       模型倾向预测"总是正常"
       ↓
       虽然准确率98%，但精准率仅6.67%
       ↓
       任何权重调整都无法充分补偿

改进方案: 增加故障样本 (98:2 → 80:20)
       ↓
       类别不平衡大幅改善
       ↓
       Focal Loss和权重调整开始有效
       ↓
       精准率提升到50-70%+
```

```

```

**千万不要**:

- ❌ 使用1.82%故障率的数据继续训练 (浪费时间)

### 验证改进是否有效

```bash
# 关键指标：故障率是否显著增加
python -c "
import pickle
import numpy as np
fh = pickle.load(open('recovery/PreGANSrc/data/simulator/fault_history.pkl','rb'))
total = (max(fh.keys())+1) * 16
faults = sum(len(v) for v in fh.values())
rate = faults/total*100

print(f'总样本: {total}')
print(f'故障样本: {faults}')
print(f'故障率: {rate:.2f}%')

if rate >= 15:
    print('✅ 故障率改进成功，可以继续训练')
elif rate >= 5:
    print('⚠️ 故障率改进中等，再次运行可能更好')
else:
    print('❌ 故障率仍然太低，需要进一步增加NEW_CONTAINERS或NUM_SIM_STEPS')
"
```
