## 📋 方案概述

### 核心策略

基于论文中的ADE（异常检测引擎）定义，在**数据层面**进行改进，而非修改模型架构：

1. **实现基于阈值的故障定义**（与论文一致，有物理意义）
2. **概率性故障放大**（模拟实际环境的故障触发机制）
3. **噪声注入**（模拟实际环境的波动特性）

### 故障定义（基于论文ADE）

| 故障类型 | 触发阈值 | 持续时间 | 物理意义 |
|---------|---------|---------|---------|
| **CPU过载** | CPU利用率 > 90% | 持续60秒 | 计算资源耗尽，任务处理延迟 |
| **RAM过载** | RAM使用率 > 90% | 持续60秒 | 内存带宽饱和，可能触发Swap |
| **网络过载** | 网络带宽使用率 > 90% | 持续60秒 | 带宽不足，数据堆积 |

**论文可解释性**：
- ✅ 基于实际物理系统的资源限制
- ✅ 90%阈值是业界常用的过载阈值
- ✅ 持续60秒避免瞬时波动导致的误报

#### 1.1 在Simulator中添加故障检测逻辑

**文件**：`simulator/Simulator.py`

```python
class Simulator():
    def __init__(self, ...):
        # ... 原有代码 ...
        
        # 故障检测配置（基于论文ADE定义）
        self.fault_config = {
            'cpu_threshold': 90.0,      # CPU过载阈值（%）
            'ram_threshold': 90.0,       # RAM过载阈值（%）
            'network_threshold': 90.0,   # 网络过载阈值（%）
            'fault_duration_required': 60.0,  # 持续60秒
        }
        
        # 故障持续时间跟踪器：{host_id: {'cpu': duration_seconds, 'ram': duration_seconds, ...}}
        self.fault_duration_tracker = {}
        
        # 故障历史记录：{interval: {host_id: fault_type}}
        self.fault_history = {}
    
    def detect_faults(self):
        """
        检测当前interval的故障状态（基于ADE逻辑）
        返回：{host_id: fault_type}，fault_type可以是'cpu', 'ram', 'network', 或None
        """
        current_faults = {}
        
        for host in self.hostlist:
            host_id = host.id
            
            # 初始化跟踪器
            if host_id not in self.fault_duration_tracker:
                self.fault_duration_tracker[host_id] = {
                    'cpu': 0.0,
                    'ram': 0.0,
                    'network': 0.0
                }
            
            # 获取当前资源使用情况
            cpu_usage = host.getCPU()  # 百分比
            ram_size, _, _ = host.getCurrentRAM()
            ram_usage = 100.0 * (ram_size / host.ramCap.size)  # 百分比
            
            # TODO: 网络带宽使用率（需要根据实际情况实现）
            # network_usage = self._calculate_network_usage(host)
            
            # 检查CPU过载（持续60秒）
            if cpu_usage > self.fault_config['cpu_threshold']:
                self.fault_duration_tracker[host_id]['cpu'] += self.intervaltime
            else:
                self.fault_duration_tracker[host_id]['cpu'] = 0.0
            
            # 检查RAM过载（持续60秒）
            if ram_usage > self.fault_config['ram_threshold']:
                self.fault_duration_tracker[host_id]['ram'] += self.intervaltime
            else:
                self.fault_duration_tracker[host_id]['ram'] = 0.0
            
            # 判断是否发生故障（持续60秒）
            if self.fault_duration_tracker[host_id]['cpu'] >= self.fault_config['fault_duration_required']:
                current_faults[host_id] = 'cpu'
            elif self.fault_duration_tracker[host_id]['ram'] >= self.fault_config['fault_duration_required']:
                current_faults[host_id] = 'ram'
            # elif self.fault_duration_tracker[host_id]['network'] >= self.fault_config['fault_duration_required']:
            #     current_faults[host_id] = 'network'
        
        # 记录故障历史
        self.fault_history[self.interval] = current_faults
        
        return current_faults
    
    def get_fault_history(self):
        """获取故障历史记录"""
        return self.fault_history
```

#### 1.3 在标签生成时使用故障信息

**文件**：`recovery/PreGANSrc/src/utils.py`

```python
def form_test_dataset_with_ade_faults(time_data_raw, fault_history, interval_time):
    """
    基于ADE逻辑生成故障标签（替代统计方法）
    
    参数:
        time_data_raw: 原始时间序列数据 [n_timesteps, n_hosts*3]
        fault_history: 故障历史记录 {interval: {host_id: fault_type}}
        interval_time: 每个时间步的间隔时间（秒）
    
    返回:
        anomaly_data: 异常标签 [n_timesteps, n_hosts]
        class_data: 故障类型 [n_timesteps, n_hosts] (0=正常, 1=CPU, 2=Network, 3=RAM)
    """
    n_timesteps = time_data_raw.shape[0]
    n_hosts = time_data_raw.shape[1] // 3
    
    anomaly_data = np.zeros((n_timesteps, n_hosts), dtype=bool)
    class_data = np.zeros((n_timesteps, n_hosts), dtype=int)
    
    # 将interval映射到时间步索引
    for interval, faults in fault_history.items():
        if interval < n_timesteps:
            for host_id, fault_type in faults.items():
                if host_id < n_hosts:
                    anomaly_data[interval, host_id] = True
                    # 故障类型映射：'cpu' -> 1, 'network' -> 2, 'ram' -> 3
                    if fault_type == 'cpu':
                        class_data[interval, host_id] = 1
                    elif fault_type == 'network':
                        class_data[interval, host_id] = 2
                    elif fault_type == 'ram':
                        class_data[interval, host_id] = 3
    
    return anomaly_data, class_data
```

### 阶段2：概率性故障放大 ⭐⭐⭐⭐⭐ **第二步**

- ✅ 模拟实际物理系统的非线性特性
- ✅ 当资源使用接近上限时，系统更容易发生故障（热节流、资源竞争等）

**实施步骤**：

```python
def getCPU(self):
    ips = self.getApparentIPS()
    cpu_base = 100 * (ips / self.ipsCap)
    
    # 概率性故障放大（仅在训练阶段，模拟实际环境的故障触发机制）
    if hasattr(self.env, 'training') and self.env.training:
        # 危险区：CPU > 80%
        if cpu_base > 80.0:
            # 以一定概率强制进入故障区（>90%）
            # 这个概率可以根据实际数据分析得出，或从论文中参考
            fault_probability = 0.35  # 35%概率（可根据实际情况调整）
            
            if np.random.random() < fault_probability:
                # 强制进入故障区（91%-99%）
                cpu_fault = np.random.uniform(91.0, 99.0)
                return cpu_fault
    
    return cpu_base

def getCurrentRAM(self):
    size, read, write = 0, 0, 0
    containers = self.env.getContainersOfHost(self.id)
    for containerID in containers:
        s, r, w = self.env.getContainerByID(containerID).getRAM()
        size += s; read += r; write += w
    
    # 概率性故障放大（仅在训练阶段）
    if hasattr(self.env, 'training') and self.env.training:
        ram_usage_percent = 100.0 * (size / self.ramCap.size)
        
        # 危险区：RAM > 80%
        if ram_usage_percent > 80.0:
            fault_probability = 0.35  # 35%概率
            
            if np.random.random() < fault_probability:
                # 强制进入故障区（91%-99%）
                fault_usage = np.random.uniform(0.91, 0.99)
                size = self.ramCap.size * fault_usage
    
    return size, read, write
```

**参数调整建议**：
- `fault_probability = 0.35`：可以根据实际数据分析调整
- 危险区阈值（80%）：可以根据实际情况调整（75%-85%）

### 阶段3：噪声注入 ⭐⭐⭐⭐ **第三步**

**目标**：模拟实际环境的波动特性

**预期效果**：精确度 50-65% → **55-70%**

**论文可解释性**：
- ✅ 实际环境的数据充满噪声和波动
- ✅ 仿真环境的数据过于平滑，缺乏真实性
- ✅ 添加噪声使数据分布更接近实际环境

**实施步骤**：

```python
def getCPU(self):
    ips = self.getApparentIPS()
    cpu_base = 100 * (ips / self.ipsCap)
    
    # 概率性故障放大（阶段2）
    if hasattr(self.env, 'training') and self.env.training:
        if cpu_base > 80.0:
            if np.random.random() < 0.35:
                cpu_base = np.random.uniform(91.0, 99.0)
                return cpu_base
    
    # 噪声注入（仅在训练阶段，模拟实际环境的波动）
    if hasattr(self.env, 'training') and self.env.training:
        # 动态噪声：负载越高，波动越大（与实际环境一致）
        noise_std = cpu_base * 0.10  # 10%的波动（可根据实际情况调整）
        noise = np.random.normal(0, noise_std)
        cpu_noisy = np.clip(cpu_base + noise, 0, 100)
        return cpu_noisy
    
    return cpu_base

def getCurrentRAM(self):
    size, read, write = 0, 0, 0
    containers = self.env.getContainersOfHost(self.id)
    for containerID in containers:
        s, r, w = self.env.getContainerByID(containerID).getRAM()
        size += s; read += r; write += w
    
    # 概率性故障放大（阶段2）
    if hasattr(self.env, 'training') and self.env.training:
        ram_usage_percent = 100.0 * (size / self.ramCap.size)
        if ram_usage_percent > 80.0:
            if np.random.random() < 0.35:
                fault_usage = np.random.uniform(0.91, 0.99)
                size = self.ramCap.size * fault_usage
    
    # 噪声注入（仅在训练阶段）
    if hasattr(self.env, 'training') and self.env.training:
        # 动态噪声：负载越高，波动越大
        noise_std = size * 0.05  # 5%的波动（可根据实际情况调整）
        noise = np.random.normal(0, noise_std)
        size = max(0, size + noise)
    
    return size, read, write
```

## 🔍 关键设计决策

### 1. 为什么只在训练阶段启用故障放大和噪声？

**原因**：
- 训练阶段需要足够的故障样本
- 测试阶段应该使用"真实"的仿真数据，评估模型在真实场景下的性能
- 如果测试阶段也启用，会导致评估结果不准确

**实现**：
- 通过`self.env.training`标志控制
- 在数据收集阶段设置`training=True`
- 在测试阶段设置`training=False`

### 2. 为什么使用90%阈值和60秒持续时间？

**原因**：
- 与论文中的ADE定义一致
- 90%是业界常用的过载阈值
- 60秒持续时间避免瞬时波动导致的误报
- 有明确的物理意义，便于在论文中解释

### 3. 为什么概率性故障放大使用35%概率？

**原因**：
- 这是一个可调参数，可以根据实际数据分析得出
- 35%是一个合理的起始值（不会太多也不会太少）
- 可以通过实验调整，找到最佳值
